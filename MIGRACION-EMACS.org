* Contexto y decisiones tomadas
** Decisiones confirmadas
- Destino: Emacs vanilla + ~use-package~ (se abandona Doom).
- Formato: Elisp modular en ~init.d/~ + GNU Stow + git.
- Teclado: se mantiene modal con ~evil~ y líder ~SPC~ (sin cambios de muscle memory).
- Alcance: *todo* (núcleo, Org, LSP, git, RSS/media, IA, extras) + tema visual *gruvbox*.
- Ubicación: todo dentro de ~.config~ → ~$XDG_CONFIG_HOME/emacs/~ (soportado nativamente por Emacs 31, confirmado en el manual: "XDG-compatible ~~/.config/emacs/init.el~").
- Emacs: el 31.1 del sistema (CachyOS). Sin build propia, sin Elpaca: ~package.el~ + ~use-package~ + native-comp.
- LSP: *lsp-mode + lsp-ui + capefy* (decisión razonada en la sección 3.1).
- *Datos*: se conservan las rutas definidas en la config de Doom: ~/Org, ~/Workspace, ~/Library, ~/.elfeed. No se cambia ni una variable de directorio de datos.
- *No es una config paralela*: es una *migración*. El código propio se porta 1:1 y los assets se mueven; al final ~doom/~ desaparece del repo.

** 1.2 Deuda técnica y conflictos detectados
1. *Doble cliente LSP en JS/TS*: ~tide~ enganchado a ~js-mode~/~typescript-mode~ (lisp/lsp.el:239-241) convive con ~lsp-deferred~ (lisp/lsp.el:261-262). Dos clientes LSP en el mismo buffer, con Peek y saltos duplicados.
2. *emms se inicializa en cada arranque*: ~(emms-all)~ y ~(emms-default-players)~ dentro de ~:config~ sin ~:defer~ (media.el:43-45) → escaneo de ~~/Music~ + spawning de mpv al inicio.
3. *Pin redundante*: ~(package! llm)~ (packages.el:79) fuerza una versión fuera de la resolución de el-pa, justo la dependencia que ya declara ~ellama~.
4. *Doom ya no usa ~after!~*: la config usa ~after!~ en ~20+ lugares (deprecated desde Doom 2023); la ruta moderna es ~:custom~/~:config~ dentro de ~use-package!~.
5. *Módulos :lang inflados*: 18 lenguajes habilitados (common-lisp, data, go, php, rest, nix, yaml...) sin ninguna toolchain instalada salvo Rust. Cada uno son paquetes + grammars.
6. *Regex roto*: dotenv-mode con ~"\\.env\\.?.*\\'"~ (config.el:157) → la comilla simple literal nunca casa.
7. *Hooks conflictivos*: ~format +onsave~ de Doom convive con ~(lsp-enable-on-type-formatting nil)~ y con ~+format-on-save-enabled-modes~ definido en lsp.el:258 (pertenece a config, no a lsp).
8. *PDF duplicado*: Doom:~pdf-tools~ + ~TeX-view-program-selection 'PDF Tools'~ (config.el:435) mientras el sistema ya tiene ~zathura~ como visor org-global.
9. *Definiciones duplicadas*: ~+my/doom-dir~ se define en config.el:57 *y* en lisp/org.el:3. Igual ~+my/org-work-dir~ (config.el:224 / org.el:120).
10. *Macros de Doom a portar 1:1*: ~use-package!~, ~map!~, ~after!~, ~add-hook!~, ~add-transient-hook!~, ~defadvice!~, ~load!~, ~set-file-template!~, ~doom-first-input-hook~, ~doom-after-init-hook~, ~doom-cache-dir~, ~doom-user-dir~, ~IS-LINUX~, ~doom-modeline-mode~, ~+format-on-save-enabled-modes~.
11. *Agenda estática*: ~org-agenda-files~ se calcula una sola vez con ~directory-files-recursively~ (org.el:123) → los archivos nuevos no aparecen hasta reiniciar.
12. *~require-final-newline 'nil~* (config.el:140): valor con tipo raro (símbolo) en lugar de boolean; funciona pero es accidental.
13. *Ruido menor*: ~go-mode-hook~ engancha lsp aunque Go no esté instalado; ~sbcl~ configurado como ~inferior-lisp-program~ sin SBCL en el sistema.
14. *Tema a reemplazar*: ~themes/noctalia-theme.el~ (catppuccin-like, ~#1e1e2e~) será reemplazado por gruvbox + paleta Noctalia solo para el fondo si lo querés.

** Criterio de nombrado
#+begin_quote
~init.d/~ tiene solo dos entradas: ~core/~ es la base que todo lo demás
consume, y ~modules/~ agrupa un directorio por dominio opcional. El *orden
de carga* lo decide la lista ~my/init-files~ de ~init.el~, no el nombre
del archivo.

Así un archivo puede depender de cualquiera listado arriba sin obligar a
inventar nombres como ~core/ui.el~. Los directorios dan el contexto; la
lista da el orden; el nombre no codifica nada.
#+end_quote

** 3.1 Cliente LSP: decisión y paridad con VSCode
*Requisito declarado: reconocimiento equivalente al de VSCode.* Eso no lo da el protocolo solo —lo da la *capa de UI* del cliente.

| Capacidad VSCode                    | ~eglot~ (built-in)      | *lsp-mode + lsp-ui*                    |
|-------------------------------------+-------------------------+----------------------------------------|
| Hover con docs markdown, en ventana | solo echo-area de eldoc, texto plano | ~lsp-ui-doc-mode~, child frame, markdown |
| Peek definition / references        | no existe (buffer ~xref~) | ~lsp-ui-peek-find-definitions/references~ |
| Peek workspace symbol               | no                       | ~lsp-ui-peek-find-workspace-symbol~      |
| Quick fix / code action (bulb)      | manual, sin UI           | ~lsp-execute-code-action~ + sideline     |
| Diagnósticos                        | flymake ✓                | flycheck + ~flycheck-diagnostics~ ✓       |
| IntelliSense con docs en popup      | corfu + capf ✓           | *capefy* (Cape + Corfu) ✓                |
| Outline / breadcrumbs               | ~imenu~                  | ~lsp-ui-imenu~ + breadcrumbs headerline  |
| Semantic tokens (LSP 3.17)          | ✓                        | ✓                                       |
| Inlay hints                         | ~eglot-momentary-inlay-hints~ | ~lsp-inlay-hints~ (comunidad)      |
| Auto-import en TS                   | manual                   | ~lsp-completion-enable-auto-import~      |
| Format on save + organize imports   | ✓                        | ✓                                       |
| Debug (DAP)                         | no                       | ~dap-mode~                              |
| Startup                             | ~0~ (built-in)           | +0.2~0.4 s (controlable con ~:commands~) |

*Decisión: lsp-mode + lsp-ui + capefy.*
#+begin_quote
Motivos: (1) ~eglot~ no trae capa de UI — habría que reconstruirla con paquetes de comunidad menos maduros; (2) ya tenés ~lsp-ui-doc~, ~lsp-ui-peek~ y tus funciones de doctor funcionando, así que la migración es *trasladar*, no reconstruir; (3) ~capefy~ es el estándar actual y ya venís usando company.
#+end_quote

Mitigación del costo de startup: cargar ~lsp-mode~ con ~:commands~, enganchar ~lsp-deferred~ por modo, y activar ~lsp-auto-configure~ solo en los lenguajes de la lista recortada.

#+begin_src emacs-lisp
;; init.d/modules/langs/lsp.el — esqueleto, se completa en la Fase 2
(use-package lsp-mode
  :defer t
  :init
  (setq lsp-idle-delay 0.3
        lsp-completion-provider :capf     ; lo consume capefy
        lsp-headerline-breadcrumb-enable t
        lsp-auto-configure nil            ; control manual: solo los modos de la lista
        lsp-log-io nil)
  :hook ((rust-ts-mode . lsp-deferred)
         (python-ts-mode . lsp-deferred)
         (typescript-mode . lsp-deferred)
         (js-mode . lsp-deferred)
         (web-mode . lsp-deferred)
         (sh-mode . lsp-deferred)
         (yaml-mode . lsp-deferred)
         (json-mode . lsp-deferred)
         (markdown-mode . lsp-deferred)))

(use-package capefy
  :after lsp-mode
  :config (cape-configure))

(use-package lsp-ui
  :after lsp-mode
  :config
  (setq lsp-ui-doc-enable t
        lsp-ui-doc-position 'at-point     ; igual que tu config actual (lisp/lsp.el:222)
        lsp-ui-doc-max-height 8
        lsp-ui-doc-max-width 72
        lsp-ui-doc-show-with-cursor t
        lsp-ui-doc-delay 0.5
        lsp-ui-peek-enable t
        lsp-ui-sideline-enable nil))       ; apagado, como hoy
#+end_src

* 4. Plan por fases (ejecución paso a paso)
** P0 — Cimientos (día 1) · Riesgo bajo · Es la base de todo
Objetivo: Emacs usable con modal, leader, theme y completion.

Pasos:
1. ~paru -S emacs~ (ya está) + crear carpeta ~emacs/.config/emacs~ en el repo.
2. Escribir ~early-init.el~ (archives, native-comp, GC tuning) e ~init.el~ que hace ~dolist load de init.d~.
3. ~stow emacs~ → verifica que ~~/.config/emacs/init.el~ carga con ~emacs --batch -Q -l ~/.config/emacs/early-init.el~.
4. ~core/keys.el~: evil + ~general~ + which-key. Portar TODOS los prefijos ~SPC~ que ya usás (n,j,D,y,m,l,e,c,o,W).
5. ~core/ui.el~: gruvbox (+ *gruvbox-material* si querés iconos Nerd Font), doom-modeline, centaur-tabs, fuentes (Cascadia Mono NF + Alegreya), hl-line, relative numbers, blink-cursor, remove-top-bar, splash.
6. ~core/buffers.el~: vertico + posframe, corfu+cape, dired+dirvish+fd, project, consult-buffering, vlf, so-long.
7. ~core/editing.el~: snippets, multiple-cursors, word-wrap, format-on-save (propio, sin el DSL de Doom), treesit-font-lock.
8. Mover ~assets/sounds~, ~assets/images~ y ~assets/latex-classes~ desde ~doom/~, y portar ~+my/create-directories~ (config.el:260-266) *sin cambiar las rutas* (~/Org, ~/Workspace, ~/Library).

Criterio de aceptación:
- [ ] ~emacs~ arranca sin errores (~M-x debug-init~ limpio).
- [ ] ~SPC~ muestra which-key; ~SPC o -~ abre dired; ~SPC o p~ abre project switcher.
- [ ] ~M-x corfu-complete~ funciona en ~python-mode~ / ~rust-mode~.

** Hallazgos que cambiaron el plan
1. *Evil 1.15 reescribió su API.* ~evil-normal-map~ → ~evil-normal-state-map~; ~evil-escape-delay~ → ~evil-esc-delay~; ~evil-escape-key-sequence~ ya no existe. Se usa el paquete ~evil-escape~ para conservar la secuencia =kj=. *~evil-mode-disable~ también fue eliminado*: ahora se desactiva Evil listando los major modes en ~evil-emacs-state-modes~.
2. *~:init~ no es ~:custom~.* =:init= corre *antes* de cargar el paquete, así que su ~defcustom~ sobrescribe el valor. Ocho ajustes (escape =kj=, estilo y alto de centaur-tabs, persp-keymap, yas-snippet-bases, yas-key-bindings, vlf-batch-size-remote, visual-fill-column-width) se perdían en silencio. Movidos a ~:custom~.
3. *Variables que ya no existen:* ~magit-blame-heading-format~ (→ ~magit-blame-time-format~), ~corfu-global-matches~, ~corfu-echo-persistent~, ~corfu-cycle-on-no-match~, ~corfu-order~, ~smartparens-strict-mode~, ~smartparens-undo-backward~, ~smart-backspace-deletes-quote~. Todas verificadas una por una contra el código del paquete instalado.
4. *~general~ perdió el leader.* No existen ni ~general-leading-key~ ni ~general-defmap~. Se sustituyó por ~my-leader~ con un keymap propio.
5. *~capefy~ fue absorbido por ~cape~*: ya no hay ~cape-configure~ ni ~cape-auto-complete~; los backends se añaden a ~completion-at-point-functions~.
6. *Paquetes que ya no se publican:* ~gruvbox-material~, ~vi-frm~, ~consult-fd~, ~corfu-suggest~.
7. *Built-ins mal tratados:* ~consult~, ~consult-buffering~, ~project~, ~dired~, ~vc-git~, ~flyspell~; con ~use-package~ intentaba instalarlos desde un archivo.
8. *APIs de consult eliminadas:* ~:buffer-templates~ y ~consult-buffer-save-window-config~.
9. *Archives rotos:* ~elpa.elpa.org~ no resuelve y NonGNU ELPA se movió a ~elpa.nongnu.org/nongnu~.
10. *~package-initialize~ es obligatorio* en ~early-init.el~.
11. *Emacs 31.1 no evalúa pares punto literales sin cotizar.* Esto también rompe ~use-package :custom~ cuando el valor contiene un par punto dentro de una lista cotizada: use-package lo cotiza y el reader falla. Por eso ~yas-snippet-bases~ va en ~:config~.
12. *Las barras superiores:* se agregaron ~my/hide-chrome~ en ~after-make-frame-functions~ y ~emacs-startup-hook~ (equivale al módulo ~remove-top-bar~ de Doom), además de ~internal-border-width~ y ~vertical-border-width~ a ~nil~.
13. *El config dir es un symlink al repo.* Emacs escribía ahí el cache de compilación nativa, los workspaces de persp y los auto-saves: cientos de archivos sin trackear. Todo el estado de runtime se movió a ~~/.cache/emacs~ y ~~/.local/share/emacs~, con entradas en ~.gitignore~ como red.
14. *~persp-mode~ no crea su directorio.* Fallaba con "No such file or directory" en cada guardado; ahora se crea explícitamente.
15. *~basic-save-buffer~ recibe un argumento* (el buffer), así que el advice del salto de línea debe aceptarlo con ~&rest~.
16. *Los bordes no pueden ser ~nil~.* doom-modeline resta los accesores de ventana sin proteger: ~(- (window-pixel-width) (window-scroll-bar-width) (window-right-divider-width) ... )~. Con ~right-divider-width~ en ~nil~, ~window-right-divider-width~ devuelve ~nil~ y el modo de línea muere con "Wrong type argument: integerp, nil". Ahora todos los bordes valen ~0~ (idéntico en pantalla, pero entero). El smoke test verifica esta aritmética.
17. *Evil instalado no es Evil activo.* Se habían portado los atajos y la secuencia =kj= pero nunca se llamaba a ~(evil-mode 1)~; además ~(evil-set-default-keybindings)~ ya no existe en Evil 1.15 y abortaba el resto del bloque ~:config~.
18. *Bug upstream en Evil 1.15:* ~evil-mode-buffers~ se declara con ~(defvar evil-mode-buffers)~, que la marca especial pero la deja void, y ~evil-normal-post-command~ la lee en cada comando en Normal state. Da "Error in post-command-hook (evil-normal-post-command): (void-variable evil-mode-buffers)". Presente tanto en NonGNU ELPA como en MELPA; se parchea en la config asignándole ~nil~.
19. *~defadvice~ está roto en este Emacs 31.1:* ~:before~, ~:around~ y ~:override~ fallan con "Eager macro-expansion failure: (wrong-type-argument listp :KEYWORD)". Toda la config usa ~advice-add~, que sí funciona.
20. *persp y Emacs 30+:* para guardar su estado, persp crea un frame temporal invisible y llama a ~delete-other-windows~ sobre él con la ventana seleccionada aún en el frame principal. Emacs 30 pasó a señalar eso y persp avisa en cada guardado. Un ~advice-add~ sobre ~persp-delete-other-windows~ omite esa llamada: el resultado es idéntico porque persp igual devolvía ~nil~, solo sin el ruido.
